03 · COMMODITIZATION

正在变成中间件

课程框架互动网页演示文稿用户旅程 PRD界面原型模拟数据研究综述 代码骨架测试用例传播文案分析草稿

文档完整、原型精美、功能上线，不再自动等于价值成立。

“商品化”不等于质量完全相同，而是达到一般可用门槛的成本下降。专业判断仍重要，但不能只靠产出形式收费。来源：综合报告第二节。

核心判断：不要把 AI 节省的时间重新填满更多低价值产出，而要投入问题定义、研究、现场验证与系统服务。来源：综合报告第一、二节。这里是战略推论，不是外部市场规模测算。

05 · THE EVIDENCE CHAIN

真正的产品，
是一条证据链

真实问题→价值假设→严谨研究→PRD / 原型→模拟 / 工程→现场使用→数据证据→产品沉淀→市场扩张
↺

市场与现场反馈，持续回到研究和产品。

这是三次讨论的第一条共同骨架。市场不是末端，研究也不是上线后的证明环节；所有角色共享同一条事实链。来源：综合报告第三节。

06 · RESEARCH UPSTREAM

研究必须进入产品上游

研究问题基线 / 对照评价量表证据标准
→
产品架构

我们能证明什么，以及不能证明什么

上线后才想如何验证，往往已经错过最关键的数据。

研究前置不是增加流程，而是减少无证据开发。它直接决定产品字段、埋点、评价机制和可支持的市场主张。来源：综合报告第三节“研究必须进入产品上游”。

07 · SIMULATION ≠ REALITY

模拟可以回答

系统是否
可能工作

提前验证字段、界面、流程和分析逻辑。

现场才能回答

用户是否
真的这样用

真实采用、行为变化、教育效果与责任边界。

快速原型用于更早获得反馈，不用于绕过工程质量。

这是一页重要边界。模拟数据降低试错成本，但不能替代真实场景。工程化强度由用户规模、数据敏感度和责任决定。来源：综合报告第三节“模拟数据”“工程化边界”。

08 · FROM TOOL TO SYSTEM

Agentic system 改变了
工作的基本单位

过去人 → 工具 → 一次输出

完成一个动作

下一阶段目标 → 多步骤 → 状态 → 反馈 → 再执行

真正的分水岭不在产品是否叫 Agent，而在系统是否能围绕目标组织多步执行、保存状态、根据检查结果继续，并沉淀经验。来源：综合报告第四节。

09 · THREE ENGINEERING LAYERS

Context、Harness、Loop
缺一不可

C

Context

系统知道什么

背景 · 数据 · 规则 · 状态
H

Harness

系统能做什么

工具 · 权限 · 测试 · 回滚
L

Loop

系统如何变好

检查 · 反馈 · 修正 · 沉淀

认知基础 + 行动边界 + 进化机制 = 可承担责任的生产系统。

Context 不是把材料塞得更多；Harness 同时提供能力与边界；Loop 不是自动放任修改，而是受评估、可审批的改进。来源：综合报告第五节。

10 · ORGANIZATION ENGINEERING

新的组织工程，
由五个组件构成

Agent Team并行分工+ Skill能力复用+ Workflow协同顺序+ State过程可见+ Evidence可信与责任

组织知识不仅要“写下来”，还要能够被执行、测试、版本化和复用。

这五项是未来最小组织骨架。Skill 必须有输入边界、样例、负责人、失败处理和评估；State 让长任务可接续；Evidence 说明为什么可信。来源：综合报告第六节。

11 · A NEW WORK RHYTHM

并行 · 异步 · 远程 ·
持续循环

人目标与判断
调研原型数据测试
人检查与取舍
修正验证归档
人最终责任

人集中在判断点，Agent 在判断点之间持续执行。

异步不是晚一点回消息，而是系统在无人看守时仍受控推进；远程是执行能力可存在于不同环境。失败要可暂停、重试、回滚和接管。来源：综合报告第七节。

Agentic workflow 不是工程方法，而是通用组织方式。每次执行都应为下一次留下资产。来源：综合报告第十节。

17 · GOVERNANCE BY DESIGN

成本、权限与治理
必须从第一天进入架构

模型分层复杂度 / 风险 / 时效 预算约束阈值 / 告警 / 停止 最小权限读 / 写 / 发 / 删 全程追溯来源 / 调用 / 版本 分级验证自动检查 / 人工签署 故障恢复暂停 / 重试 / 回滚

治理不是附加成本，而是进入学校与真实业务的前提。

Agent 会放大调用量、数据访问和错误传播。效率与治理必须一起设计。来源：综合报告第十二节。
