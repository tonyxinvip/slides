04 · THE LOOP

现代 Agent 的核心不是更长回答，
而是行动—观察循环

RReason形成下一步判断
→
AAct调用工具改变状态
→
OObserve读取真实反馈
→
RReason更新计划
↺
验证重试停止升级给人

没有可验证反馈，Agent 只是把一次生成延长成多次生成。

ReAct 的关键不是让推理可见，而是让模型通过工具改变环境，再读取环境反馈。真正的工程问题是：什么时候继续、验证、重试、停止，什么时候交还给人。
05 · RELIABILITY

2023 年的自主 Agent，
为什么没有真正跑通？

0.9530≈ 21%

如果 30 个关键步骤每一步只有 95% 成功率，长程任务的联合成功率会迅速坍塌。

模型准确率不足工具接口不成熟缺少状态验证失败后无法恢复成本高、产出低

有 loop 不等于能自治；每一步必须可验证、可恢复、可回滚。

这是 MetaGPT、AutoGPT 等早期系统的共同困境。它们证明了可能性，但当时模型、MCP、工具调用和运行环境都不足以支撑长程任务。
06 · MULTI-AGENT LESSON

MetaGPT 的真正启示：
先强化一个 Agent

弱 Agent × 多角色

复制岗位名称

交接、压缩与共享偏差不断叠加；很多协作只发生在 Markdown 文档里。

强 Agent × 责任边界

围绕产出物拆分

只有 Context、权限、工具或独立验证责任不同，拆分才产生净价值。

多 Agent 的单位不是“角色”，而是需要被独立管理的责任。

不是否定多 Agent，而是改变拆分原则。先让单体拥有强工具、强 Context 和验证能力，再根据责任边界拆分，避免机械照搬人类组织结构。

10 · THE ENGINEERING TRIAD

Context、Harness 与 Loop
构成三层工程

CONTEXT

认知环境

任务、知识、记忆、状态、历史与当前意图。

HARNESS

行动环境

工具、权限、runtime、tests、反馈与恢复机制。

LOOP

持续执行

继续、验证、重试、停止、升级与长期改进。

Prompt ⊂ Context · Context + Harness + Loop = Agent Work System
三者不是并列功能，而是嵌套系统：Context 决定它理解什么，Harness 决定它能做什么，Loop 决定它如何持续到完成。

15 · EDUCATION
