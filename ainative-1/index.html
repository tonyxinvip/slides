07 · THE RELIABILITY WALL

每一步只错一点，
走三十步也可能完全跑偏

0.9530≈ 21%

只作风险示意：假设每一步都有 95% 的把握，而且彼此独立，连续 30 步全部做对的机会也只剩约 21%。现实中，前一步的错还会带偏后一步。

理解错目标选错工具记错进度不会恢复不知何时停

让 Agent 循环起来并不难；难的是每一步都有检查，出错能退回，危险时会停手。

先提醒听众：这个公式不是任何产品的实测，只是帮助理解“误差会累积”。AutoGPT 时代最直观的问题就是：系统看起来一直很忙，却可能在错误方向上不断加速。长任务因此需要检查点、重试、回滚和交还给人。

10 · THE MULTI-AGENT LESSON

多放几个 Agent，
不会自动变成好团队

只有角色名

大家都在转述

每个 Agent 都说一点相似的话，交接越多，信息损失和错误传播越严重。

有不同责任

每一棒都有凭据

资料、权限、工具、产物或验收责任不同，分工才可能带来额外价值。

可复用的不是一张“虚拟公司”名单，而是清楚的交接规则和中间产物。

这里给出综合判断，不把它冒充成某篇论文的原话。多 Agent 常见误区是给相似模型贴上不同职位，再让它们反复讨论。真正有用的分工，必须让每个 Agent 拿到不同资料、拥有不同权限、使用不同工具，或者承担独立验收责任。
11 · WHY CODING FIRST

代码世界为什么最早跑通？
做错了会立刻报错

写代码→编译→测试→读错误→修复↺
结果容易判断

编译器、测试、lint、CI 会直接暴露失败。

过程留有痕迹

文件、差异、提交和日志都可以复查。

出错能够退回

沙箱、分支和回滚把影响限制在小范围。

Coding Agent 领先，不只因为模型会写代码，更因为它身边有一整套现成的检查工具。

把它讲成一个简单对比：文章“写得好不好”很难自动判断，但代码能不能编译、测试能不能通过，机器马上就知道。Agent 能把错误信息读回来，再修下一轮；文件、diff、commit 又让每次动作都留痕。这套环境比模型本身更早成熟。

ACI 可以大白话解释为“给 Agent 用的键盘、屏幕和操作规程”。人能在复杂 IDE 里凭经验找路；Agent 更需要少量明确动作，以及压缩后的可读反馈。SWE-agent 的重要性在于说明：同一个模型，换一套行动接口，表现就可能明显不同。

任务目标工作说明参考范例可信资料当前工作桌面长期记忆当前进度历史记录用户意图
资料多，不等于准备充分→有限窗口里，要留下此刻最相关、可信、可用的信息

它把提示词扩展成一张动态工作桌：该看的及时出现，不该看的暂时收起，来源和进度都说清楚。

工程文章Anthropic · 29 Sep 2025
Context Engineering 可以大白话解释成“给 Agent 收拾开工桌面”。桌上要有任务、规则、参考资料和当前进度；资料太多也会挡路，所以旧信息要收起，需要时再取。它的历史根系是 2020 年的上下文学习和 RAG，后来又吸收了长期记忆、IDE 上下文选择和仓库说明。
24 · HARNESS ENGINEERING · NAMED 2026

Harness Engineering：
给 Agent 一间合格的工作间

工具

动作明确、数量有限、可以组合

运行环境

隔离、可复现，不影响真实系统

门禁

最小权限，越界前先审批

反馈

结果和错误能被机器读懂

验收

独立测试，不让自己给自己打分

恢复

有检查点，能重试，也能回滚

工具只是工作间里的一样东西；运行环境、门禁、反馈、验收和恢复缺一不可。

工程文章OpenAI · 11 Feb 2026
Harness 原意接近“把能力约束并连接起来的一整套装置”。可以把它讲成 Agent 的工作间：有什么工具，在哪运行，能进哪些门，做完看到什么反馈，谁来验收，出错怎样退回。SWE-agent、MCP、沙箱和测试都是它的前史，2026 年 OpenAI 的工程文章把这套做法进一步系统化。
25 · LOOP ENGINEERING · AN EMERGING LABEL

Loop Engineering：
别让它在错误方向上傻跑

目标计划行动看结果检查总结重试停止 / 叫人
做对了吗预算够吗还要试几次需要审批吗异常交给谁经验写到哪里

循环的目的不是一直运行，而是每一轮都回答：做对了吗？还要继续吗？该不该叫人？

方法前史ReAct · 2022Reflexion · 2023
Loop Engineering 还是一个正在形成的工程标签，不要把它说成已经定型的学科。它的构成很早就出现了：ReAct 是想一步、做一步、看结果；Reflexion 增加失败后的文字总结；生产系统再加成功标准、预算、最大重试、审批和异常升级。
26 · SIX QUESTIONS → FOUR SYSTEM LAYERS

六个工程问题，最后落到
三层工作系统 + 一层治理

CONTEXT · 工作桌面

先形成判断

任务、资料、记忆和当前进度放到眼前。

HARNESS · 工作间

再安全行动

工具、运行环境和反馈限定能做什么。

LOOP · 工作节奏

持续到结果

检查、重试、停止或叫人，把行动带到终点。

Context 负责“知道什么” · Harness 负责“能做什么” · Loop 负责“接下来怎么办”
治理横跨三层权限 · 预算 · 审计 · 异常升级
这里回收第 2 页的六个问题：任务理解、事实获取和记忆进入 Context；工具与观察进入 Harness；持续完成由 Loop 控制；安全委派则不是第四个顺序步骤，而是横跨三层的 Governance。四者共同构成 Agent Work System。

28 · HUMAN IMPACT

AI Worker 的出现，
把人从操作者推向任务编排者

SYNC

即时协作

人与 Agent 共享当前窗口，快速澄清和共同调试。

ASYNC

后台委派

人离开当前会话，Agent 保留环境和状态继续工作。

PARALLEL

多线推进

多个独立任务同时运行，人负责优先级、验收和冲突处理。

远程、异步、并行，让稀缺资源从“亲自执行的时间”迁移到“定义、判断与验收的带宽”。

把这页放在工程框架和工程重心外移之后，作为第一部分最后一个外部影响判断。Codex 等产品表明，异步与并行会把执行时间和人的在线时间解耦；这里仍只讲通用工作方式，具体组织含义留到第二部分。
